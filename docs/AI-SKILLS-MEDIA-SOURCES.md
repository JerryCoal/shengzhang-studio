# 媒体生成 Skills：依据与接线说明

核对日期：2026-10-14。规则版本：`2026.10.14.2`。

三份规则面向本程序现有图片与视频调用，使用原创中文表达。它们直接指导目标媒体模型，不先调用另一个大模型编写方案，不要求媒体模型输出 JSON。官方示例可证明接口形式与提示词建议，不能证明这些规则已经提高点击率或带来运营转化；本次没有调用付费媒体模型做效果测试。

## 本轮接线必须处理的细节

1. **参考图用途。** 当前尾帧输入顺序是“产品图（如有）→首帧”。有产品图时首帧是第二张；没有产品图时首帧是第一张。应由程序写清对应关系，不固定假设首帧总是图片 2。
2. **真正的时长与声音。** 当前视频接口收取 5、8、12 秒及声音开关，但旧 `mediaPrompt` 调用只传 `purpose` 和 `prompt`。注入新规则时补充实际值，避免规则只能泛泛提到“本次时长”。请求体仍控制实际规格。
3. **标题和无字模式。** `title` 模式新增文字只渲染明确给定标题，不让图像模型凭正文发明第二套文案。标题过长时先让用户调整；不要悄悄换词。`none` 不额外添加宣传文字，真实参考图原有包装与标识照实保留；平台强制水印仍由 API 参数控制，不能靠提示词取消。成图仍需人工检查错字及模式是否落实。
4. **控制提示词体积。** 三份 Skill 各保留约 300–450 个中文字的稳定规则；整份注入再叠加原有资料会超过官方简洁建议。因此每次只选一份，删去重复的步骤描述，保留已确认事实和用户原始要求的边界，仅加入当前步骤需要的资料。复杂输入仍可能超过 300 字；这不是强制上限，不应为压缩而裁掉重要事实、截断标题或遗漏否定条件。
5. **不把能力混在一起。** 不把新模型文档中的多参考视频、视频编辑或自动联网能力搬入当前两帧工作流。没有改变现有图片尺寸、图片模型参数、视频参数或服务商选择；`image-2` 接口参数未在本子任务重查或修改。
6. **规则可追溯。** 构建时编译对应正文与版本，生成配方记录实际使用的 Skill 名称和版本。不要将用户自装文案 Skills、旧素材规则快照或整套规则库自动加入媒体请求。

## 建议验证

- 用相同产品资料比较封面 `none` / `title` 两种请求，确认只有后者带明确标题绘制要求，二者都不附宣传正文或视频运镜。
- 对有、无产品图的尾帧请求分别检查参考图说明，保证首帧绑定正确。
- 检查视频提示词中的时长、声音开关与请求体完全一致；5 秒任务不要求多个跨场景事件。
- 检查每次请求只含当前步骤的 Skill，并保留真实产品事实与成品版本。
- 真实生成验证需另行使用用户选择的模型与预算；检查主体识别、标题准确度、端点一致性、动作完成度，不能只以接口返回成功判定视觉质量。
