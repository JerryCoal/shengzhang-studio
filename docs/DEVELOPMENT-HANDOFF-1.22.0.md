# v1.22.0 开发交接

## 改动范围

本次在正式应用中落实用户选定的飞书式清爽协作方向。重点是分组导航、平台账号入口、紧凑工作台和设置排版，不改生成、发布、采集或加密存储协议。

- 主应用导航与工作台：按现有工作流程整理入口，减少首屏装饰，保留项目上下文和任务状态。
- `src/pages/SettingsPage.tsx`：9 类设置按三个组展示；所有子面板继续挂载，切换分类不清空表单。键盘方向键、Home/End 与原会话内分类记忆保留。
- `src/settings-layout.css`：桌面分组侧栏、窄屏下拉菜单；API 与 Skills 使用容器宽度调整布局。应在现有全局样式之后加载。
- `openPublishingSettings(go)`：先保存分类，再派发 `studio-settings-open`，事件 `detail` 为 `publishing`。设置页监听该事件，保证已挂载时也能跳到正确分类。
- 应用版本与 MCP 客户端标识更新为 `1.22.0`；服务工作线程资源缓存版本更新，不改变用户数据库。

## 数据与安全边界

无需数据库或用户资料迁移。工作站用户、项目、平台账号层级不变，账号凭证与任务归属继续沿用现有实现。UI 不得把平台账号快捷入口解释为新增登录方式、批量发布授权或跨账号共享。

累计保留 v1.21.0 的 20 个 AI 工作步骤、默认规则与每步一份自装规则、启动时快照、修订冲突和禁用/删除回退。Windows 版按当前请求使用规则；网页自装 Skills 暂不向中转后端传输，选中时仍明确阻止远程生成，不可为适配 UI 静默取消该边界。

外部 MCP、平台登录、实际发布确认、敏感词、原文证据检查和预算限制均维持原行为。本次未授权或执行实际平台发布。

## 后续维护

新增导航项需同时核对桌面、窄屏、大字号和键盘操作；设置新增分类应维护分组与焦点顺序。继续优先考虑账号矩阵的明确归属，不为界面统一而合并不同账号数据。

验证需使用合成资料或隔离工作区，不读取个人数据、密钥、Cookie。检查首次加载、设置切换、平台账号快捷入口、生成期间导航、表单保留及横向溢出。具体结果统一记录到 [VALIDATION-1.22.0.md](VALIDATION-1.22.0.md)。

构建依次进行 Skills 编译检查、TypeScript、必要回归测试、桌面/Web/静态构建，再运行 `scripts/build-windows.mjs` 和 `scripts/package-windows.mjs`。分发包应包含本版使用说明、更新记录、交接与验证文档；不包含任何个人数据。本版不上传 GitHub。

前序业务实现见 [v1.21.0 开发交接](DEVELOPMENT-HANDOFF-1.21.0.md)。
