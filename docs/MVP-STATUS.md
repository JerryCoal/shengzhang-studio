## 工程选择

React + TypeScript + Vite 承担共用交互；Capacitor 承担安卓/iOS 容器与分享；Node + Express 提供统一服务，SQLite 持久化。选择此路线是为了在早期保持一套核心页面与业务逻辑，便于电脑和手机共同验证。

本次没有将应用发布到外部域名，没有创建平台开发者账号，也没有执行任何真实社交平台投稿。

## 一致性与边界

- 品牌事实与运营要求分别输入。生成提示要求缺失事实保留为待补充，但该要求不是对模型输出事实性的自动保证，仍需人员确认。
- 策略在创建时保存资料快照。确认后任务和发布快照独立保留；成品标题修改会要求重新制作画面。
- 图片素材与配音可在局部重做时替换，历史成品仍保留。草稿更改不会重做已有成品。
- 服务端事务保护持久数据；项目和成品更新有乐观并发检查。尚未实现完整团队协作冲突解决。
- API 密钥在 Windows 本机通过 DPAPI 加密保存，支持设置页填写、检查与删除；模型分工可独立配置。手机原生安全存储待实现，个人密钥禁止远程提交与调用。完整密钥不返回客户端。登录限制、来源检查、输入校验和文件签名校验已实现。
- 模型费用预留、用量估算和不确定请求记录已实现；本地制作费用为零，不显示虚构消耗。
- 示例项目、示例作品和示例评论均有标注；示例作品不计入真实发布完成状态。
- 原文不会被模型或模板重写。分类是可修改的辅助信息，不以正负情绪删除批评。

## 尚未覆盖的草案指标

人工工时、修改轮次汇总、成果采用率、每份采用成果的成本分摊、评论整理耗时、平台自动化覆盖比例尚未形成统一报表。当前有策略版本、成品版本、活动记录和模型费用记录可支持后续扩展。

## 建议的下一轮实测

选一个真实品牌/产品，填入可核实的资料和产品图；在设置页配置个人 API，实际走一轮策略确认、内容制作、人工发布、评论导入与反馈采用。记录效果和人工操作，再决定优先接通的生成模型与平台能力。
