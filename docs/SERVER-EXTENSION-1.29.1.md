# v1.29.1 服务器扩展交接说明

本版保留接入服务器的接口与业务边界。前端整理为连续的内容工作流，没有把生成、保存、发布等能力改成只能在页面里运行的逻辑。当前可运行的共享服务器方案是单台主机上的团队服务；这不等于已经具备多节点数据库、分布式任务队列或多租户云平台。

本文按本仓库实现说明扩展点，不包含真实密钥、用户数据或上线配置。代码路径均相对于项目根目录。

## 1. 当前运行方式

| 方式 | 数据与接口位置 | 已有边界 |
| --- | --- | --- |
| Windows 个人工作站 | `server/profiles.mjs` 为登录用户创建独立 `createApp`，工作区在该用户目录的 SQLite 中 | 用户工作区与凭证分别派生密钥；平台连接、任务和内容仍有平台账号归属 |
| 普通 Node 服务 | `server/index.mjs` → `createStore` → `createApp` | 可托管 `dist/` 和 `/api`；默认只监听本机。对外监听要求工作区密码，允许来源需明确配置。此入口不是团队成员系统 |
| 团队主机 | `server/team.mjs` → `createTeamApp` → `createApp` | 同事使用独立成员身份访问共享工作区。Node 监听回环地址，前置 HTTPS 反向代理，管理员管理连接与成员 |
| 静态体验版 | `src/api.ts` 分派至 `src/local-api.ts`，使用浏览器加密本地工作区 | 支持直接草稿、单篇要求和资料/经验的本地保存与编辑；不具备主机平台登录、服务端密钥或本机后台服务能力 |
| 独立联网网页版 | `src/web-api.ts` 的浏览器本地工作区 + `server/web-relay.mjs` 的有限操作中转 | 中转不是共享数据库。请求内临时工作区和凭证只用于允许的操作；私人身份、Skills、研究与新知识字段不可借此上传 |

团队版与独立联网网页版是不同部署方式。把独立网页版的中转地址改掉，不会自动变成团队版。

## 2. 前端与 HTTP 接口已经分开

`src/api.ts` 是前端请求入口：

- 普通构建向 `${API_BASE}/api${path}` 发送 JSON。`API_BASE` 取构建变量 `VITE_API_BASE_URL`，未配置时使用同源 `/api`。
- 请求携带 `X-Studio-Client: studio-v1`；登录后按当前流程携带 `Authorization: Bearer …`。
- `IS_STATIC` 与 `IS_WEB` 分别走本地适配和网页版适配，不能用 `API_BASE` 绕过这两个构建模式的限制。
- 团队模式目前要求通过配置的同源团队入口访问；CSP、Host、Origin 和回环代理检查会继续生效。普通服务的跨源配置能力不代表团队部署默认允许任意跨域前端。

优先部署形式仍是一个正式域名同时提供前端静态文件和 `/api`，由 Caddy 或 nginx 终止 TLS，再转到本机 Node 端口。这样无需把桌面 UI 重写为另一套产品。反向代理、域名、证书、进程管理和备份是部署工作，不由此次界面改版自动完成。

`server/app.mjs` 的 `createApp(store, options)` 已可注入存储、凭证保险箱、模型配置、服务连接、请求传输及静态目录。测试可注入模拟传输，不需要调用真实收费服务。

## 3. 新增业务模块与接口合同

`server/content-workflow.mjs` 管理直接创建内容、单篇要求、参考资料和经验；声明在 `server/content-workflow.d.mts`。它不执行 HTTP、数据库写入或外部模型调用，由路由在事务中调用。函数会校验并修改传入的工作区对象，生成标识和时间，因此不能把它理解为完全无副作用的数学纯函数。

`src/local-api.ts` 复用同一模块处理对应本地操作，`src/web-api.ts` 也将这些保存操作交给浏览器本地适配器，避免浏览器和 Node 各写一套归属及版本规则。静态体验版与独立联网网页版均开放资料/经验的新增、编辑、停用、保存来源后新建草稿；资料仅在此浏览器按登录用户加密保存。带账号身份与这些私人资料的联网生成仍需 Windows 或团队版，本地保存不会获准向独立网页中转发送这些字段。

| 接口 | 输入要点 | 返回与行为 |
| --- | --- | --- |
| `POST /api/projects/:id/content-drafts` | `requestId` 必填 UUID；`accountId`；`kind: image/video`；`requirement`；可选 `title`、`knowledgeIds` | `{ result: Asset, state }`。仅创建草稿，不调用模型、不发布。兼容现有结构，保留关联策略和账号快照 |
| `PUT /api/projects/:id/assets/:assetId/brief` | `expectedRevision`；`requirement`；可选 `knowledgeIds` | `{ result: Asset, state }`。校验版本与已有账号归属后更新单篇要求 |
| `POST /api/projects/:id/knowledge` | `kind: reference/experience`；`title`；`text`；可选 `requestId`、来源字段、`accountId`、`expiresAt` | `{ result: KnowledgeEntry, state }`。保存资料或待验证经验，不调用模型 |
| `PATCH /api/projects/:id/knowledge/:entryId` | `expectedRevision` 必填；可更新资料字段、`active` | `{ result: KnowledgeEntry, state }`。版本不符拒绝覆盖 |
| `POST /api/projects/:id/knowledge/preview` | 可选 `accountId`、`assetId`、`query`、`knowledgeIds` | 直接返回 `KnowledgeContext`，不是 `{ result, state }`。只读预览，无模型费用 |

当前主要约束：单篇要求最多 4,000 字符；知识标题最多 200 字符、正文最多 12,000 字符、来源 URL 最多 2,000 字符；知识引用最多 8 个且不能重复。知识条目 `accountId: ""` 表示当前项目共享，`expiresAt: null` 表示没有到期时间。以服务端 schema 为准，不只依赖前端限制。

通用失败返回为 `{ error: string }`，已有部分模型失败还会携带诊断字段。保留 400 输入无效、401 未登录、403 无权限、404 不存在、409 版本或状态冲突、413 过大等含义。客户端遇到 409 应保留本地输入、重新读取并由用户核对，不能改用最新版本号直接覆盖。

前端 `App.tsx` 在变更完成后重新读取当前状态，避免较慢请求携带的旧全工作区快照覆盖另一个已完成操作。以后改为分页、增量事件或实体响应时，应一起修改这一协调层，而不是让各页面自行合并。

## 4. 版本、幂等与账号边界

### 版本冲突

- 单篇内容、知识条目、编辑草稿、发布快照有各自的版本或状态约束；项目 `revision` 和团队 `teamRevision` 用于更新感知，不能替代所有实体的编辑条件。
- 发布记录保留 `assetId + assetRevision + accountId`。同一版本已经给 A 账号安排发布，不表示 B 账号也已完成；修改后的新版本同样不能被旧记录覆盖。
- `server/workspace-view.mjs` 只用于派生查看状态。无归属的历史内容不能因为存在某个账号的发布记录就被标为全局已发布。
- 历史生成中的身份、规则和资料快照要保留。更改当前账号、规则或资料，不应回写历史内容的依据。

### 幂等范围

- 新草稿创建要求 UUID `requestId`；知识创建支持可选 `requestId`，本版保存界面会提供。
- `project.contentRequests` 保存请求类型、规范化输入和结果 ID。同项目同请求编号与相同输入重试返回原结果；编号重复但输入不同返回 409。
- 目前每项目最多保存 2,000 条该请求记录；这是当前本地结构的容量限制，不是服务端任务队列，也没有自动过期清理合同。
- 不能据此声称所有历史接口或全部外部模型操作都已经幂等。付费操作需保留各自的费用预留、服务商任务 ID、状态查询和不确定结果处理；超时不能直接当成失败再次付费提交。

### 身份范围

始终区分工作站成员、项目/品牌、平台账号三类身份：

- 团队成员来自认证会话与 `request-actor.mjs`，角色为管理员、创作者或发布员。平台账号 ID 不是用户身份，也不能代替成员权限。
- 团队工作区共享项目；当前还不是按项目成员授权的多租户系统。未来接入企业多租户必须在服务端新增 tenant/workspace 的查询及写入约束。
- 内容优先使用自身 `contentBrief.accountId`，历史内容可从 `creationTrace` 恢复归属。资料按当前内容账号过滤；停用、过期或其他账号的显式引用应被拒绝，而不是悄悄改用另一份资料。
- 页面 `accountScope` 仅筛选查看范围，不改变平台登录、不修改内容账号。来源采集账号也不等于创作账号。
- 平台连接与凭证沿用现有按账号隔离；发布前仍核对实际目标账号和用户授权。新增服务器不构成自动或批量发布授权。

## 5. 当前存储是什么，迁移数据库要替换什么

`server/store.mjs` 使用 Node 内置 SQLite，同步 `get()` / `mutate(callback)` / `close()`。工作区主体存放在单行 JSON 中；`mutate` 使用 `BEGIN IMMEDIATE`，成功提交，异常回滚。`createStore(':memory:')` 是测试可用的内存 SQLite，不代表生产数据只保存在 JavaScript 内存。

传入 key 时工作区正文加密保存；未传入 key 的普通 `server/index.mjs` 入口没有同样的正文加密。个人 profiles 和 team 入口传入工作区密钥。不要把某一入口的保护条件描述为所有部署模式默认具备。

团队入口另外保存成员数据库、模型/连接配置和凭证保险箱。`server/team-storage.mjs` 从主机主密钥派生工作区及凭证密钥；Windows 使用当前主机用户的 DPAPI 保护主密钥，其他受支持路径使用主机文件权限。迁移到新主机或运行用户不能只复制数据库文件并假定旧密钥仍可解锁。

`server/team-store.mjs` 在共享存储外投影成员个人偏好：当前创作账号、MCP 当前账号、未完成表单、外观、引导及项目创作选择等。它还递增 `teamRevision`。数据库替换必须保留这种“共享内容、个人选择”的区分。

建议按两阶段迁移：

1. **先保持 HTTP 合同，替换服务端数据访问。** 建立工作区级事务仓储，并保留当前校验和业务函数。当前调用点依赖同步 store，不能直接把 `get()` 换成 Promise 返回值；远程 PostgreSQL/MySQL 驱动通常需要同时将事务边界和路由调用改为可等待的异步接口。事务内不等待模型、Redfox 或平台网络请求。
2. **再拆分实体与大文件。** 将成员/会话、项目、账号、内容及版本、发布快照、评论、指标、知识、请求记录、任务与费用账本拆为可索引实体。图片、视频现有多处为 data URL；规模扩大时需要对象存储、受控读取和独立媒体引用，不能只把整个 JSON 原样放进远程库就宣称完成扩容。

至少保留以下数据库约束：所属工作区与实体 ID、账号归属、乐观版本检查、`workspace/project + requestId` 幂等唯一性，以及同内容版本和账号的发布重复约束。返回值、权限和加密边界仍按原接口保留；改变历史数据结构需提供迁移、备份、核对和回滚方案。

## 6. 团队鉴权与多进程前必须补的部分

`server/team-app.mjs` 已有成员密码校验、登录限流、内存会话、用户停用检查、角色权限和操作人审计。`teamPermission` 及少数具体路由继续做权限判断；不是仅由页面隐藏按钮决定权限。团队 Node 默认监听回环地址，由受信任的前置入口访问。

下列部分目前依赖单进程，扩展为多个 Node 实例前需要替换或协调：

- 登录会话与部分限流计数在 `Map` 中；多实例需要共享会话/限流或另一套明确的身份认证方案。
- `createApp` 的 `activeJobs` 是进程内集合，后台计时器与服务连接也在进程内；多个实例不能靠它互斥同一项目的付费调用。
- 前端 `useBackgroundTasks` 是当前客户端的任务提示与页面保留机制。v1.29 会冻结并恢复 `WorkspaceTarget`，方便返回原作品；它不负责主机重启后的任务调度。
- 服务端部分生成流程保存了阶段、远端任务号、费用预留和重启后的“不确定”状态，可在既有范围内查询恢复；不等于所有请求都可自动恢复或安全重放。

未来需要持久任务表、明确的领取租约/锁、费用预留事务、提供商任务号、结果确认和可审计的重试策略。进程崩溃后的未知结果先核对，不应由队列自动重复付费或重复投稿。当前没有生产级分布式队列、跨节点锁或无条件 exactly-once 执行保证。

## 7. 独立网页中转的限制继续保留

`server/web-relay.mjs` 使用操作白名单，临时内存 store 只服务本次允许的操作，不能代理任意 URL，也不持久保存用户工作区。`server/web-skill-privacy.mjs` 明确过滤/拒绝 `knowledge`、`knowledgeContext`、`contentBrief`、`contentRequests` 及私人身份和 Skills 等字段；直接创作关联的内容也有限制。

因此未来要做“浏览器访问公司服务器”，应沿团队/服务器接口建立经过认证的持久工作区，而不是把私人字段加入现有中转白名单来绕过限制。若确需改动传输范围，应单独定义数据归属、告知和权限合同，并补充隐私与合并回归。

## 8. 验收与后续开发入口

本版已增加的边界测试包括 `tests/workspace-navigation.test.mjs`，覆盖路由定位、私人要求不进入 URL、账号与版本发布状态，以及无归属历史资产。`tests/content-workflow-browser.test.mjs` 验证浏览器本地保存经加密重新登录后保留，且不同登录用户隔离；`tests/knowledge-library-ui.test.mjs` 验证静态和联网网页模式开放本地保存入口，并保留忙碌时的操作限制。内容与知识业务测试以 `server/content-workflow.mjs` 及其路由为目标；团队权限、账户隔离、费用与网页隐私测试继续沿用已有测试集。

接服务器时至少验收：两成员并发编辑返回明确冲突；相同创建请求重放只生成一份；账号 A 的内容和资料不被账号 B 的浏览范围改写；发布和费用记录不可因超时重复执行；停止或重启主机保留不确定状态；完整备份可恢复工作区及必要密钥；私人内容不通过独立网页中转泄露。联调使用模拟服务传输，真实收费和发布操作单独按原流程确认。

本次版本提供的是可继续扩展的接口和清楚的边界。数据库拆分、对象存储、多实例部署和任务队列仍是后续工程，未在 v1.29.1 中宣称已经完成。


## v1.29.1 研究取数修复

研究仍由现有 Node HTTP 服务执行。`POST /api/projects/:id/research/run` 增加可选布尔值 `redfoxXhsExpansion`，默认 false；仅对新采集的小红书 Redfox 发现模式生效。新界面在费用确认中明确展示补充读取上限。近七天/近三十天搜索改为最新排序，再由本地校验精确发布日期、正文和选定条件。

共享模块 `server/redfox-research-plan.mjs` 约束请求计划：每次最多 3 个关键词；未授权补充读取时每词 1 页、无详情；授权后每词最多 2 页、整轮最多 3 个详情。费用上限由同一计划供服务端与页面计算。不得通过重试、切换提供商或扩大日期范围绕过确认。

`research.summary` 保存本轮取数与筛选数量，和保留的历史参考分开。旧客户端和历史记录无需迁移。错误诊断使用安全的本地分类，不回传原始上游密钥或请求内容；没有合格证据时不调用分析模型。账号归属、项目互斥与 assertActive 中止检查继续生效。
