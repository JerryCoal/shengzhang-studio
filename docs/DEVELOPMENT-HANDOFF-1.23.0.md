# v1.23.0 开发交接

新增目的 `brief.type = nurture`，文字输入保存在 `brief.nurture = { topic, scene, copyPrompt }`。普通项目不要求该字段；养号渠道限定小红书、抖音、TikTok 和 Instagram。兼容旧字段仅为工作流补齐必要名称与描述，用户 Prompt 不是事实或可直接发布的正文。

`newProject` 原子创建本地内容方案、确认并建立图文任务，不发模型请求，不产生发布计划。任务使用 `briefSnapshot` 保留本次主题、场景与写作要求。后续 AI 文案沿用既有 copy 路由、Skills、敏感词筛选和预算；模型写作要求明确区分日常分享与产品营销。

场景图复用当前项目 `imageData`，不放入 Brief 或文本模型输入。新建请求仅养号允许顶层 `imageData`；格式、大小、文件头由 `validateSceneReference` 检查。已有项目走 media 路由。每次封面请求启动时捕获参考图字节，异步结果沿用原项目与素材 ID，不自动覆盖已修改版本。

`ProjectEditor` 新增专用输入与图片暂存；文字沿用自动草稿保存。图片在未提交前只存于当前挂载工作区，关闭再打开可恢复，退出或刷新不持久化。创建成功清理暂存，工作站用户切换不共享。

`Studio` 展示养号步骤，文案与配图分别调用；`Cover` 支持上述养号图文渠道，保留候选核对与手动采用；`renderPoster` 针对养号使用场景图或文字布局，不绘制虚构商品包装。导出与发布复用现有流程，账号仍在发布中心显式选择。

测试应使用合成资料、模拟服务与隔离工作区。没有新增平台授权、无人值守发布或付费服务。网页自装 Skills 不传中转后端的既有限制继续保留。真实模型质量与各平台投稿权限仍需在用户授权下联调。

本次验证结果见 [VALIDATION-1.23.0.md](VALIDATION-1.23.0.md)。前序布局与 Skills 交接见 [v1.22.0](DEVELOPMENT-HANDOFF-1.22.0.md)。
