# 评论工作流与运营数据调研 / v1.5.0

## 从已有流程出发

沿用项目方案的“触发 → 数据 → AI 判断 → 流程分支 → 人工核对 → 结果 → 监测 → 反馈”。本次落地评论与数据这一段，不另建完整的可视化工作流引擎。

原有程序已有评论导入、六类标签、AI 分类、复盘和建议采用；主要缺口是分类依据不可见、筛选不参与分析、没有待核对队列，以及作品指标没有独立的数据区域。

## 已查阅的官方实现思路

- [n8n Text Classifier](https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.text-classifier/)：每个类别有明确描述，可多标签分类，无法匹配的内容可进入 Other 分支。本项目据此保留“其他”与待核对状态，不丢弃无法判断的原文。参考架构，自行实现，没有复制其源码或引入依赖。
- [Dify 多平台内容工作流官方教程](https://docs.dify.ai/en/guides/application-orchestrate/creating-an-application)：输入标准化、条件判断、迭代和结构化输出分别承担不同职责；确定性的格式化交给程序。本项目让程序完成统计、范围校验和引用核对，模型承担语义分类与复盘。

## 本次实现

1. 评论导入：沿用已存在的作品绑定和去重机制，原文不被分类流程改写。
2. 本地初筛：按主题线索归类，保留命中的原文片段；价格询问不自动记负面，否定、转折、混合情绪与模糊回应进入核对队列。
3. AI 分类：单次最多 30 条，并按输入长度收缩；输出评论 ID、多主题、情绪、理由、原文片段和是否需要核对。不遗漏、不重复、不接受不存在的引用。不自动付费重试，用户确认后才调用。
4. 人工核对：可调整主题、情绪、相关性和备注；后续规则与 AI 不覆盖人工结果。请求期间新保存的人工结果也受到保护。
5. 范围复盘：按作品、平台、主题、核对状态和导入日期筛选，后端使用明确评论 ID；空集合不退回全部数据。规则复盘和 AI 复盘都保留本次输入范围、时间、来源、模型与依据。
6. 采用与验证：继续沿用原有“查看依据 → 采用/修改后采用 → 品牌经验 → 下期策划”流程；历史复盘可回看，采用可撤销。
7. 运营数据：新增独立导航，展示发布、评论、作品指标台账。平台累计指标目前手工录入，保留采集时间、来源、修订版本和缺失值。

## 数据口径

- 评论条数不是人数、线索或订单；意向不能推断为购买行为。
- 主题可多选，主题计数和占比不能相加。
- 导入时间与评论发表时间分开；范围过滤以导入时间为准。
- 评论采集可能不完整，不以导入量冒充平台评论总数。
- 平台未知指标保存为 null，显示“—”；真实的 0 保留为 0。
- 每个作品只用最新一条采集快照汇总，累计快照不相加；作品采集时点不同时不计算周期增长。
- 运营数据默认排除示例作品。评论页的示例数据有显式开关和标签。

## 后续方向

优先完善平台导出文件的字段映射和错误报告，再接具备授权条件的指标接口。积累同口径多期数据后增加趋势、异常与实验对照。转化率、获客成本和 ROI 需先明确业务事件、分母、时间窗口与归因方式；本版只保留规划说明，不生成这些数值。

## 本次边界

没有自动回复、群发、平台自动发布或新爬虫接口。AI 通过已有 OpenAI / DeepSeek 模型设置调用，费用和失败处理沿用现有机制。原文与指标保存在原有本地加密工作区；手动导出的报告包含选中评论或指标，应按团队需要分享。AI 判断不代表经过真实业务样本校准的准确率。
