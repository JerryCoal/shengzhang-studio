# AI 宣传运营 App：第一版需求草案

更新日期：2026-09-12。本文用于讨论产品和制作原型；平台接口接通与效果尚未实测。

## 1. 已确定的产品方向

面向品牌／市场运营人员，服务新品／服务上市、日常品牌传播两个场景。发布目标是运营人员管理的自有普通个人／创作者账号，优先考虑小红书、抖音，并预留其他平台。

用户输入文字资料、宣传目标、目标受众、重点卖点和其他要求，调用指定的 GPT-5 生成宣传策略与 Prompt。人员修改确认后，系统自动制作文案、图片和视频，进入发布流程。发布后获取评论、筛选整理并形成反馈，影响下一轮宣传。

当前范围覆盖自有账号内容发布与反馈分析。反馈在本文中体现为运营复盘和下一轮策划建议。付费广告投流、自动回复评论尚未纳入已确定需求。

核心流程：资料与目标 → 策略与 Prompt → 人员修改确认 → 内容制作 → 发布 → 评论分析 → 下一轮策略。

## 2. 建议的第一版页面

| 页面 | 主要操作 | 交付结果 |
| --- | --- | --- |
| 项目与品牌资料 | 新建上市项目或日常传播项目，维护产品资料与参考素材 | 可复用的资料与项目要求 |
| 策略与 Prompt | 查看方案、修改宣传方向和制作要求、编辑 Prompt | 已确认的方案版本与制作任务 |
| 内容制作 | 查看文案、图片、视频进度，编辑和局部重做 | 可预览的内容及版本记录 |
| 发布中心 | 选择账号、发布版本和时间，提交或转入平台发布流程 | 作品链接、发布记录和待处理事项 |
| 评论与复盘 | 同步或导入评论，筛选归类，检查分析依据 | 复盘建议和待验证的内容假设 |
| 下期策划 | 采用、修改或暂不采用建议，生成下一轮计划 | 携带反馈依据的新策略与 Prompt |

页面数量和布局属于设计建议，适合先制作可点击原型验证。

## 3. 需求输入

| 要素 | 内容 |
| --- | --- |
| 原始资料 | 品牌与产品介绍、产品事实、已有文案、图片和视频素材 |
| 宣传目标 | 认知、咨询、购买引导等目标及希望用户完成的行为 |
| 受众与针对点 | 面向谁、什么使用场景、什么问题、优先表达哪些卖点 |
| 内容要求 | 目标渠道、内容类型、数量、视频时长与视觉参考 |
| 品牌要求 | 语气、视觉风格、必须保留的信息和表达限制 |
| 时间与成本 | 项目截止时间、发布计划、内容生成费用上限 |

系统先整理资料，将产品事实、运营要求和待补充信息分开呈现。缺少价格、性能、客户案例等事实时，标为待补充。

## 4. 策略确认与自动制作

GPT-5 输出宣传主题、核心信息、渠道方向、内容清单、脚本与分镜，以及各项制作 Prompt。运营可以直接修改可读的策略卡片，也可以展开编辑 Prompt。

自然语言修改应同步到受影响的制作任务。例如，将重点从价格优惠改为使用体验后，系统更新相关标题、文案要求和镜头要求，并列出变化。确认后锁定本次执行所用的方案版本。

GPT-5 用于策略、Prompt、文案及反馈分析；图片、视频和配音交给相应生成模型或工具，App 管理素材传递与合成。GPT-5 官方模型页列出文字输出、函数调用及结构化输出能力；其原生输出不包含图片、音频和视频。开发时保留用户指定的 GPT-5，并验证实际账号的模型可用性。[OpenAI Docs：GPT-5](https://developers.openai.com/api/docs/models/gpt-5)

建议先提供小红书图文、抖音短视频两种内容模板。视频首条流程采用产品素材、分镜、配音、字幕和合成预览，允许替换某张图或重做某个镜头。

生成任务需要显示进度、预计与实际消耗、失败原因，支持暂停后续任务和在费用上限内重试。已完成且未受修改影响的素材应当复用。

保留成品预览和局部修改入口。是否在最终成品阶段逐条确认，或按项目预设规则提交发布，属于后续交互设计选择；人员修改策略是已确定环节。

## 5. 普通个人／创作者账号的发布与评论接入

运营使用的账号类型、App 开发者主体、应用类型、应用已获权限和账号授权范围，需要分别验证。普通创作者账号并不直接说明 App 的开发者主体是否符合申请条件；用户授权也不能替代平台给应用开通能力。

| 能力 | 已查到的官方资料 | 第一版处理建议 |
| --- | --- | --- |
| 抖音分享投稿 | 官方资料提供移动／网站应用分享发布路线 | 应用接入获准并验证后，带入平台发布流程；保留素材导出 |
| 抖音后台代发布 | 官方资料列出开发者主体、正式网站应用和业务场景要求 | 实际获批且账号适用后启用自动发布；申请结果尚未确定 |
| 抖音评论获取 | 官方能力页列出视频评论管理，包含评论及回复列表，并要求授权 | 单独核实准入、范围和普通账号适用性；获批后接入自动同步 |
| 小红书发布 | 公开分享 SDK 基于小红书 App 内的发布流程 | 经接入确认后提供分享发布；标题正文如何带入须联调验证 |
| 小红书评论获取 | 本次公开资料检索尚未确认适用于本产品的通用评论接口 | 继续确认官方能力，同时支持用户提供的评论粘贴或文件导入 |

抖音后台代发布的官方说明列出的申请条件涉及开发者主体为企业、党政机关或事业单位、正式网站应用，以及指定使用场景。这些条件不能直接等同于要求每个发布账号都认证为企业号。[抖音官方场景与接入说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/open-capacity/solutions/Life-Service-Solutions/marketing)

抖音视频评论管理的公开能力页列出移动应用、网站应用和小程序，实际权限与配额仍需确认。[抖音视频评论管理](https://developer.open-douyin.com/capacity-center-page/capacity-detail/7180530418775490619)

小红书分享 SDK 提供图文和视频进入 App 发布流程的能力，其公开 FAQ 提示标题与正文自动填充受限；这与后台全自动发布是不同接入方式。本次尚未完成平台申请或联调。[小红书分享能力](https://agora.xiaohongshu.com/doc)、[小红书分享 FAQ](https://agora.xiaohongshu.com/doc/qa)、[公开账号权限说明](https://openaccount.xiaohongshu.com/docs/scope)

账号页按实际验证结果显示“自动发布”“转到平台发布”“评论自动同步”“评论导入”等可用操作。自动发布是产品目标；辅助操作是接口未满足时的可用路径。

有自动发布能力时，排期可以驱动发布任务；需要用户操作的平台，排期对应待办提醒。转入平台、上传完成与发布成功分别记录。只有拿到可靠结果或用户明确回填，才标记相应状态，并保留确认来源；请求结果不明时先核对，避免重复发布。

## 6. 评论分析如何影响后续宣传

评论进入系统时，关联平台、账号、作品、对应项目和制作方案版本。保留评论原文、必要的回复上下文、时间、来源及可获取的互动数据。分析页面显示采集窗口、实际样本量和最后同步时间。

筛选包括按作品、时间、关键词和主题查看；合并重复问题、标记无关内容，并保留真实批评与投诉。分类支持多个标签和人工纠正：购买咨询、价格顾虑、使用疑问、体验反馈、内容建议等。情绪倾向作为辅助维度。

每条复盘建议包含：观察到的问题、原始评论依据、出现次数、涉及作品、建议改动、适用范围和待验证点。样本不足时标为初步观察，避免把少数高赞评论视为全部受众意见。

示例场景：评论集中询问产品尺寸和携带方式。系统建议下一轮补充尺寸信息、实物比例、装包演示，并把相关镜头要求写入下期 Prompt。产品尺寸仍从产品资料中读取。

运营可采用、修改或暂不采用建议。采用的建议进入品牌经验库，下一次 GPT-5 生成策略时自动取用与当前产品、渠道和目标相关的经验。经验通过资料和 Prompt 传递给模型，保留版本与撤销记录。

下一轮内容标注本次尝试验证的改动。在数据可取得时，结合评论结构、播放和收藏等指标比较表现，并说明观察窗口；不把相关变化直接认定为宣传改动带来的因果效果。

## 7. 第一版验收场景

1. 运营输入真实资料与目标后，得到可编辑的策略、制作清单和 Prompt。
2. 修改一个核心卖点，相关制作要求同步变化；确认后按该版本执行。
3. 完成图文与一种短视频制作；重做某一素材时保留其他已采用成果。
4. 按账号实际具备的能力完成自动发布或辅助发布，记录真实结果与作品关联。
5. 获取或导入该作品评论，完成去重、归类，且复盘建议可以追溯原文依据。
6. 采用一条建议后，下次生成策略和 Prompt 时能明确看到该建议带来的变化。

记录人工总工时、修改轮次、成果采用率、每份采用成果的生成成本，以及评论整理与复盘耗时。平台发布和评论自动化覆盖范围单独统计，避免将人工操作计为已实现的自动化。

## 8. 下一步验证顺序

先用一个真实宣传项目制作可点击原型，覆盖“需求—策略修改—制作—发布—评论—下期策略”，以明确人工参与点和交付形式。

正式接入前，核实 App 开发者主体与应用类型、发布和评论权限、普通创作者账号适用范围，以及模型账号可用性和实际成本。这些是工程验证事项，尚未获得平台批准，也不构成对接口可用性的承诺。

原型可用后，以一个自有账号验证发布与评论链路；将实测结果写入账号能力表，再扩大平台与账号覆盖。
